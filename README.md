# Anki Natural Speech Skill

A local-first Codex skill specification for turning user-provided language material into audio-first Anki decks with:

- English-only explanations
- contextual chunks, collocations, and constructions
- grammar and vocabulary analysis
- semantic images
- **audio-first default cards: hear first, reveal Target second**
- mandatory native-like conversational Target audio through a configurable TTS provider
- **at least 4 natural examples for every normal word/phrase/sentence note**
- **mandatory separate audio for every pronounceable example**
- required Target/example audio physically embedded in the APKG
- optional comprehension, selective production, and selective personal-error correction cards

## Design goal

The primary retrieval sequence is:

**sound -> retrieve -> reveal written form/meaning -> reusable pattern -> spoken transfer examples**

The skill distinguishes:

**written language != careful pronunciation != natural conversational pronunciation**

It therefore uses provider-neutral speech planning before TTS instead of treating the written string as the whole pronunciation specification.

## Recommended V1

- `genanki` for `.apkg` export
- pluggable TTS provider selection (`auto` or explicit provider)
- local image generation through a replaceable adapter
- no paid API dependency by default

## First implementation milestone

Build one complete path before adding advanced features:

1. Parse one representative normal item.
2. Produce structured English-only linguistic analysis.
3. Generate at least 4 natural transfer examples.
4. Produce speech plans for the Target and every example.
5. Generate real playable Target audio plus separate audio for every pronounceable example through an allowed TTS provider.
6. Validate every required audio file.
7. Generate or attach one semantic image.
8. Build one default Listening card whose front contains audio and optional image but no Target text.
9. Export a valid `.apkg`.
10. Inspect the APKG and prove that every required `[sound:filename]` resolves to physically packaged media.

Do not auto-install or auto-download large TTS models during normal execution. First prove one complete vertical path.

## Mandatory audio contract

Every pronounceable exported Target and every pronounceable example must contain a real playable audio file generated by an allowed TTS provider.

Audio must be physically embedded in APKG media. External filesystem paths, URLs, cache-only files, filename strings, TTS prompts, and speech plans do not satisfy the requirement.

The build must fail if any required Target/example audio cannot be generated, referenced, packaged, and resolved after export.

## Card Design V2

The current card specification is documented in `docs/card-design-v2.md`.

Key rules:

- Listening is the default card.
- The default front is AudioNatural + optional semantic image.
- Target text and English meaning stay hidden until reveal.
- The back reveals Target, NaturalMeaning, the key reusable pattern, NaturalSpeech information, and 4+ spoken examples.
- Every normal word/phrase/sentence note has at least 4 complete natural examples.
- Every pronounceable example has its own real generated audio file.
- Comprehension is optional rather than the default.
- Production is selective and must avoid ambiguous reverse translation.
- Personal-error correction is selective and never the default learning stimulus.
- The TTS provider is configurable; no single provider is globally required.

## Codex fail-fast rule

Before any full batch, Codex must run a one-note vertical smoke test covering:

- 4+ valid examples;
- real Target TTS;
- real TTS for every example;
- sound-reference creation;
- APKG export;
- APKG media verification for every required file.

If the smoke test fails, stop immediately and report the first actionable blocker. Do not repeatedly retry the same deterministic failure or rebuild the whole deck.

See `docs/codex-execution-contract.md` and `docs/tts-provider-contract.md`.

## Source of truth

`SKILL.md` is normative. Config, schemas, docs, and examples must be kept consistent with it.

# Anki Audio Pipeline Skill

## Scope

This skill owns speech planning, TTS-provider selection, synthesis, audio validation, and audio caching.

It MUST NOT change card layout, example count, target text, meanings, glosses, or APKG presentation.

## Required audio inputs

For every standard note, audio is required for exactly:

1. `Target`
2. `Examples[0].Text`
3. `Examples[1].Text`

The content skill determines these texts. This skill must synthesize them faithfully and must not rewrite them.

## Provider-neutral architecture

Core audio code MUST depend on a provider interface, not a specific engine.

Conceptual interface:

```python
generate_speech(
    text,
    language,
    voice,
    speech_plan,
    provider,
    output_path,
)
```

`provider: auto` may select among allowed installed/available adapters.
No single TTS engine, including Fish Speech, is mandatory.

## Provider policy

Default policy:

- prefer local/free providers;
- do not silently use paid APIs;
- do not silently use network providers when disabled;
- do not auto-download a large model unless explicitly allowed;
- record the actual resolved provider and model in exported metadata.

## Speech planning

Before synthesis, build a provider-neutral speech plan when useful, covering:

- target language and dialect
- ordinary conversational rate
- phrase boundaries
- sentence stress
- focus
- intonation
- rhythm
- linking and connected speech
- linguistically plausible reductions

Do not alter the written Target to imitate pronunciation.
Do not create naturalness through random slurring or deletion.

## Natural-speech goal

Audio should sound like ordinary native conversation:

- natural rhythm
- plausible stress
- connected speech
- sentence-type-appropriate intonation
- realistic pauses
- normal reductions where appropriate

## Mandatory artifacts

A standard note requires THREE distinct real audio artifacts:

- Target audio
- Example 1 audio
- Example 2 audio

Each artifact MUST:

- be actually synthesized;
- exist as a non-empty playable file;
- correspond to the exact required text;
- have a stable media filename;
- be passed to the packaging layer for APKG embedding.

A filename, URL, placeholder, SSML string, prompt, speech plan, or external cache reference is not an audio artifact.

## Cache

Reuse successful audio using a stable key based on at least:

- text
- language/dialect
- provider
- model
- voice
- speech-plan version
- audio mode

Do not resynthesize unchanged valid audio unnecessarily.

## Failure policy

If a required audio item cannot be generated by any allowed provider, FAIL the build stage.

Never:

- omit one example audio;
- replace audio with a placeholder;
- export a partial note as successful;
- silently switch to a prohibited paid/network provider;
- modify card semantics to hide a TTS failure.

For deterministic errors, do not repeat the same unchanged command.

## Output contract

Return, for each required audio item:

- source text
- resolved provider
- resolved model if applicable
- local media path
- stable media filename
- file size / non-empty validation result
- optional speech-plan metadata

The packaging skill is responsible for turning the validated filename into `[sound:filename]` and verifying its presence inside APKG media.
